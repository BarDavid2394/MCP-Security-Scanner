# Iteration 003 protocol

Develop against exposed iteration 002 failures: four command import-alias misses,
one low-level command dispatcher miss, five secret-output/logging misses, and two
post-hoc boolean-environment false alarms. Retain iteration 001 regression labels.

Use the already-exposed ten-project corpus to check collateral changes. The
first development candidate exposed generic storage-key and lexical-token false
alarms; refine those before freezing and preserve both candidate run records.

Freeze actual scanner/runner hashes and archive code before reviewing fresh batch
3 source. Review all standalone Python candidates from the proposed
jspillers10/mcp-security-scanner group (57 total candidates). Defer cross-file
and duplicate-name groups that require a grouped runner; exclude cases outside
the implemented taxonomy instead of treating them as true negatives. Label
source behavior, not upstream filenames, before the first fresh prediction.

Run the frozen candidate once on locked fresh labels, then inspect failures.
A retrospective run of iteration 002's archived scanner on those same labels may
measure a paired change; it is not another independent test. Do not tune against
batch 3 predictions during this iteration. Keep the final holdout unconsumed.

Publish both development and fresh results: label counts by category, confusion
matrix, precision, recall, false-positive rate, errors, unscored findings, tests,
remaining limitations, and the next proposed fixes. Labels are assistant-reviewed
and still require independent human adjudication.
